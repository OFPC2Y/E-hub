e-hub 系统监控工具 使用说明
========================================

功能
  实时监控 CPU / GPU / 内存 / 磁盘 / 网络，可通过串口把数据发送到 HUB 显示屏。


启动
  双击 SystemMonitor.exe，会弹出 UAC 管理员权限请求，点「是」。

  ⚠ 必须授权。CPU 温度、功耗、风扇转速都要读硬件底层寄存器，
    没有管理员权限这几项一律拿不到。

  启动后面板自动打开，托盘出现图标：
    绿色 = 监控正常    红色 = 串口异常    灰色 = 未运行


CPU 温度 / 功耗 / 风扇显示 N/A
  Intel 12 代及以上 CPU，以及多数主板的风扇转速，必须依赖内核驱动
  PawnIO 才能读取。程序首次运行会自动弹窗询问是否安装。

  自动安装：弹窗点「是」，按向导走完，然后重启本程序
  手动安装：external\PawnIO_setup.exe
            右键 → 以管理员身份运行，装完后重启本程序

  装好后打开「工具 → 诊断信息」，「当前数据总览」里 CPU 温度、
  风扇、功耗三行都应该有数字。


连接 HUB 串口
  1. 菜单「工具 → 设置」，选对串口（如 COM3）
     端口列表在程序启动时读一次，之后点托盘菜单「刷新串口列表」重新读。
     设备后插上的话，先刷新一次再打开「选择串口」。
     列表读的是驱动注册信息。虚拟串口驱动的端口偶尔仍可能列不出来，
     这时直接在「设置」里手动输入端口名（如 COM3）——不影响收发。
  2. 波特率必须与 HUB 固件一致，默认为 115200

     ⚠ 两端不一致会完全收不到数据。
       一帧完整数据约 880 字节：115200 需要 0.077 秒，
       9600 需要 0.92 秒，会占满 1 秒的采集间隔，实际一帧都发不出去。

     如果串口能打开但 HUB 一直没数据，第一个要查的就是波特率。
  3. 波特率不够时程序会主动丢帧并在状态栏提示，而不是硬写半行数据
     把对端的 JSON 解析搞乱。


串口晚于程序就绪（不用重启）
  设备没插好、驱动没加载、被别的程序临时占着，都不影响程序启动：
  它每 5 秒自动重连一次，端口一出现就自动开始发送。
  运行中拔掉再插回，同样会自动恢复。

  想立刻重试：托盘图标右键 →「刷新串口列表」。

  但注意：串口连不上时面板数据照常刷新，看起来一切正常，
  实际一个字节都没发出去。以状态栏和托盘图标颜色为准——
  绿色才是真的在发。


退出
  菜单「文件 → 退出」，或托盘图标右键 → 退出。

  菜单「文件 → 隐藏到托盘」只是隐藏面板，程序继续在托盘运行。
  如果托盘图标不可用，关闭面板等同于退出程序——不会出现
  "程序没关掉又找不到入口"的情况。


托盘图标看不见？
  Windows 11 默认把新程序的托盘图标收进折叠区（任务栏的 ^ 箭头）。
  设置 → 个人化 → 任务栏 → 其他系统托盘图标 → 把 e-hub 打开。


出问题了怎么查
  菜单「工具 → 查看日志」    → 打开开发日志
  菜单「工具 → 诊断信息」    → 各传感器原始读数、串口与配置状态

  反馈问题时把这两项的内容附上即可。


文件位置
  配置文件   config.json      与 exe 同目录，删掉即恢复默认值
  运行日志   logs\ehub.log    与 exe 同目录，超过 512KB 自动轮转


注意
  - 本程序每次启动都需要管理员权限
  - 部分主板（如 ASUS B760M）不装 PawnIO 就一定读不到 CPU 传感器
  - 日志只记录开发信息，不要在反馈时附带与问题无关的个人数据
